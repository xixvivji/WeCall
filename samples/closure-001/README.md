# 합성 종료 사례 C2

모든 자료는 가상이다. 기존 `recall-001`의 미연결 출고를 수정하지 않고 별도 사건으로 실행한다. 기준 시각은 `2026-09-09T18:00:00+09:00`, 단위 EA.

## 화면에서 재현

1. 데이터 관리에서 이 폴더의 CSV 5개를 함께 등록한다. 출고와 출고 연결 파일은 헤더만 있으며 출고가 0건인 사례다.
2. `notice.md`를 원문으로 사건을 등록한다. 조건에서 등록한 데이터 버전, P1 상품 연결과 근거, 제조번호가 A01과 일치하는 규칙을 입력한다. 입력 예시는 `condition-request.json`이며 API 사용 시 `datasetId`를 등록 결과로 추가한다.
3. 검토자가 조건을 승인하고 판정한다. 재고 I1 5 EA 대상, 출고 0 EA. `expected.json`과 비교한다.
4. I1 격리 작업을 실행 담당자에게 배정한다. 담당자가 시작하고 “합성 I1 전체 5 EA 격리 확인” 증빙을 제출한다. 검토자가 현재 회차 증빙을 승인한 뒤 작업을 완료한다.
5. 종료 점검에서 대상 범위와 증빙을 검토하고 확인 항목·사유를 입력해 종료한다. 작업 완료만으로 사건이 자동 종료되지는 않는다.
6. 종료 후 판정 추가가 제한되는지 확인한다. 재개 사유를 남기고 재개한 뒤 다시 종료한다.
7. 같은 기준 판정의 대응 보고서에서 재고 대상 5 EA, 완료 작업, 종료→재개→종료 이력을 확인한다. 작업을 완료해도 원래 판정 수량과 업로드 당시 격리 상태가 바뀌지는 않는다.

## 자동 검증

로컬 합성 DB와 시연 계정 환경 변수를 준비하고 저장소 루트에서 `python3 scripts/demo_closure.py`를 실행한다. 이 스크립트는 C1 종료 차단과 C2 종료·재개·보고서를 함께 검증하며 매번 새 데이터를 만든다. 정답은 `expected.json`에 수기로 고정돼 있다. C2는 정상 종료를 연습하기 위한 최소 사례이며 실제 회사의 종료 기준 승인을 의미하지 않는다.
