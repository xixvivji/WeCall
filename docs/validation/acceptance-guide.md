# 업무 검수 진행표

AI 구현 전 사람이 확인할 업무 흐름과 정답의 기준이다. 회사 승인 자료가 아직 없으므로 우선 합성 C1·C2로 개발 검수를 진행한다. 실제 현업 인수 승인은 별도로 남긴다.

## 준비 순서

1. 검토자와 실행 담당자 계정을 준비한다. 한 사람이 진행할 때도 역할별로 로그아웃·로그인한다.
2. [C1 원문·CSV·정답표](../../samples/recall-001/README.md)와 [C2 종료용 자료](../../samples/closure-001/README.md)를 사용한다. 정답표를 먼저 읽고 화면 결과와 비교한다.
3. C1은 원본을 보존하고 증거 승인으로 새 버전을 만든다. C2는 별도 업로드·사건으로 시작한다.
4. 아래 각 행의 관찰 결과를 기록한다. 실패 시 화면·입력·기준 판정 ID·재현 순서를 남긴다. 실행하지 않은 항목은 미검증으로 둔다.

## 검수 결과 작성 카드

- 검수 구분: 합성 개발 검증 / 승인 자료 현업 검수
- 수행일·역할·검토 담당자:
- 코드 버전·환경·자료 묶음 ID:
- C1 사건/보완 전·후 판정 ID, C2 사건/판정 ID:
- 실행한 U번호 / 통과·실패·미검증 / 관찰 근거:
- 문제: 재현 순서 / 기대 결과 / 실제 결과 / 업무 영향 / 수정 후 재검수:
- 담당자 확인: 진행 가능 / 수정 후 재검수 / 자료 부족으로 보류
- 미검증 범위·다음 담당자:

자동 테스트 통과를 현업 담당자의 승인으로 대신 기록하지 않는다. 실제 자료로 전환할 때는 [자료 준비 카드](materials-checklist.md)를 먼저 작성한다. 승인 자료의 보관 위치·반출 범위는 회사가 정하며 공개 저장소에는 합성 자료만 둔다.

## 자동 검증과 연결

- `python3 scripts/validate_sample.py`: C1 수기 정답의 참조·수량 일관성.
- `python3 scripts/demo_recall.py --with-evidence --with-tasks`: C1 실제 API, 보완 전후 행별 정답·합계, 작업 완료 후 판정 불변, 보고서의 선택 판정·미확인 차단 확인.
- `python3 scripts/demo_closure.py`: C1 종료 거절, C2 고정 정답·종료·재개·보고서 이력 확인.
- 프론트에서 `npm run test:e2e`: 역할을 바꾸며 화면 흐름, 오류·충돌 복구, 보고서·모바일·입력 보호 확인. 실제 AI 호출 없이 실행한다.

시연 스크립트의 actor 문자열은 로그인 계정 전환이 아니다. 역할별 로그인 검증은 브라우저 테스트와 위 수동 검수에서 수행한다. 자동 실행은 합성 데이터와 시연 계정이 있는 개발 환경을 사용하고, 생성 데이터는 실행마다 누적된다.
