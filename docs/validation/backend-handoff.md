# 백엔드 MVP 인수와 다음 단계

기준: 한 회사 내부용, Java 21 / Spring Boot 3.5.16 / Gradle 8.7 / PostgreSQL. 여러 기업이 공유하는 SaaS의 데이터 격리는 별도 범위다.

## 기능 기준

현재 통합된 develop의 업무 기능은 CSV·사건·조건 승인·판정·증거 보완·대응 작업·증빙·첨부·종료/재개·이력·보고서·계정 관리다. 마지막 확정 검증은 백엔드 114건, 프론트 19건이다.

추가 구현 범위는 첨부 검사 어댑터, V11 검사 메타데이터, 검사 실패 시 전체 롤백/다운로드 차단 및 테스트다. 백엔드 114건 테스트와 프론트 빌드로 검증했다. 실제 ClamAV 엔진 탐지 시험은 별도다. [첨부 검사 계약](../design/attachment-scanning.md)

## 프론트 작업 인수

1. 기존 Vue 화면에서 로그인→데이터→사건→조건 승인→판정→증거/작업→종료→보고서 흐름을 다듬는다. API는 `/api/v1`이며 세션 쿠키와 변경 요청의 CSRF 토큰을 유지한다.
2. 작업 변경은 expectedVersion을 사용한다. 409 발생 시 최신 기록을 다시 읽고 사용자가 내용을 확인한 후 재시도한다.
3. 판정 수량(EA), 상품 연결, 작업 상태(건수)를 구분한다. 출고 미연결 수량은 확인 필요에 포함된다.
4. 첨부 검사 실패 422는 파일을 확인하도록 안내하고, 503은 검사 서비스 상태 확인 후 재시도한다. 파일 선택과 업무 입력은 보존한다.
5. API별 상세 계약은 docs/design 문서를 따른다. 브라우저 흐름은 frontend/e2e, 합성 인수 절차는 demo-scenarios.md를 기준으로 한다.

## AI 작업 인수 — 후속 단계

FastAPI는 기존 ExtractionClient 계약에 연결한다. 조건 초안 추출만 제공하고 상품 연결·조건 승인·판정 확정은 백엔드의 사람 승인 흐름을 유지한다. OCR과 파일 분석은 별도 설계한다. 실제 문서를 전달하기 전 회사의 허용 자료·처리 위치·보존 조건을 확정한다. 현재 실제 모델은 구현하지 않았다.

## 회사 자료/배포 결정이 필요한 잔여 항목

- 승인된 실제 또는 비식별 자료와 현업 담당자의 정답 검증: materials-checklist.md 사용.
- 실제 ClamAV 엔진 배치·서명 갱신·정상/위협/중단 인수 시험.
- 보관 기간·보존 예외·삭제 승인자 결정. 기록 삭제나 자동 파기 기능은 임의로 활성화하지 않는다.
- 배포 재개 시 HTTPS·시크릿·DB+파일 백업/복원·모니터링·부하 검증.

이 항목은 프론트/AI 개발 착수와 운영 사용 승인을 구분하기 위한 기준이다. 합성 테스트 통과가 실제 회수 업무의 적합성이나 운영 승인을 대신하지 않는다.

## 확정 검증 결과

2026-09-14: 백엔드 114건, 프론트 19건, 프론트 빌드 통과. [CI 34822411824](https://github.com/xixvivji/WeCall/actions/runs/34822411824)에서 별도 PostgreSQL 환경의 브라우저·HTTP 업무 시나리오도 통과했다. CI에서 발견한 같은 판정 재조회 중 증거 입력 폼 초기화 문제는 수정하고, 응답을 지연시켜 입력 보존을 확인하는 회귀 검증을 추가했다. 실제 검사 엔진을 통한 탐지 시험은 이 결과에 포함하지 않는다.

## 2026-09-17 PDF 원본·원문 이력 추가

V12에 `source_document`, `source_document_event`, `source_revision`을 추가했다. PDF 원본은 기존 로컬 첨부 저장소에 보관하며, 원문 변경은 새 버전으로 기록한다. AI 분석은 원문 버전을 저장하고 이전 버전의 조건 전환을 차단한다. 기존 조건·승인·판정은 자동 변경하지 않는다. 백업·정리 시 원본 PDF와 증빙 파일을 모두 포함해야 한다. [원본·수정 이력 API](../design/source-pdf.md)

## 2026-09-18 원문 재검토 관리

V13에 조건·판정의 생성 당시 원문 버전과 condition_source_review, 현재 상태 계산 뷰를 추가했다. 영향 없음 확인 전 승인·판정·증거 승인·종료를 차단하며 오래된 승인 기록은 보존한다. 미승인 초안은 사유를 남겨 철회할 수 있다. 과거 원문 버전 미기록 조건은 임의로 연결하지 않고 검토가 필요하다. [구현 계약](../design/source-revalidation.md)
