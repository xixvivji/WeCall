# CSV 작성·수정 안내

데이터 관리 화면의 **CSV 빈 양식 5종 다운로드**를 누르면 ZIP에 CSV 5개와 작성안내.txt가 들어 있다. CSV는 헤더만 포함하며 예시 행이 없다. 화면의 **CSV 항목별 작성 안내**에서 필수 여부·참조 규칙·예시를 확인하고 개별 양식도 내려받을 수 있다.

## 작성 순서

1. 상품 목록을 작성한다. `product_id`는 이 자료 묶음 안에서 유일하며 입고·출고 파일도 같은 ID를 사용한다.
2. 입고 목록을 작성한다. 제조번호와 소비기한은 모르면 빈칸으로 남긴다. `UNKNOWN`, `미상`, `-` 같은 문자열을 대신 넣지 않는다.
3. 입고 ID를 참조해 재고 목록을 작성한다.
4. 상품 ID를 참조해 출고 목록을 작성한다.
5. 실제 입고·출고 연결 기록이 있는 수량만 연결 파일에 작성한다. 근거가 없는 연결을 상품·날짜·잔여 수량으로 추정하지 않는다.
6. 자료의 기준 시각을 선택하고 CSV 5종을 함께 등록한다. 기록이 없는 종류도 헤더만 있는 파일로 제출한다.

CSV를 열거나 가져올 때 ID 열은 텍스트로 지정해 `0001` 같은 앞자리 0을 보존한다. 날짜는 `YYYY-MM-DD`, 수량은 쉼표·소수점·단위 문자를 제외한 정수 EA로 입력한다. 박스 단위 값을 그대로 넣지 않는다. Excel 등을 이용하면 **CSV UTF-8** 형식으로 저장한다. 쉼표나 셀 안 줄바꿈이 있는 값은 CSV 인용 규칙에 맞춰 큰따옴표로 감싸야 하며, 셀 값 안 큰따옴표는 두 번 쓴다. 보통 CSV 내보내기 기능이 이를 처리한다.

## 파일별 항목

별도 표시가 없는 항목은 필수다. 텍스트는 500자 이내이며 앞뒤 공백은 등록 시 제거된다. 각 파일의 첫 ID 열은 중복될 수 없다. 헤더 이름과 순서는 양식 그대로 유지한다.

| 파일 | 열 순서 | 주요 규칙 |
| --- | --- | --- |
| products.csv | product_id, name, manufacturer, pack_size, unit | 단위는 EA만 허용 |
| receipts.csv | receipt_id, product_id, lot_number, expiry_date, received_quantity, received_at | 제조번호·소비기한만 빈칸 허용; 상품 ID 참조 |
| inventory.csv | inventory_id, receipt_id, warehouse, quantity, hold_status | 입고 ID 참조; NONE 또는 HELD |
| shipments.csv | shipment_id, order_id, product_id, quantity, shipped_at | 상품 ID 참조; 같은 주문의 출고 기록은 서로 다른 출고 ID 사용 |
| shipment_allocations.csv | allocation_id, shipment_id, receipt_id, quantity | 출고·입고 ID 참조; 실제 확인한 연결만 입력 |

수량은 0~10억 정수이며 연결 수량은 1 이상이다. 한 출고의 연결 합계는 출고 수량을 넘을 수 없고, 한 입고의 재고+연결 출고 합계는 입고 수량을 넘을 수 없다. 연결하는 상품은 같아야 하고 출고일은 해당 입고일 이전일 수 없다. 입출고 날짜는 입력한 기준 시각의 날짜 이하여야 한다.

파일당 5 MiB(5,242,880바이트), 데이터 기록 10,000개, 전체 파일 26 MiB까지 허용한다. 파일 이름은 바꿀 수 있지만 올바른 업로드 항목에 선택해야 한다.

## 오류가 나타나면

- **파일 종류 / 선택 파일**: `inventory.csv`는 검증 종류이며 그 아래 실제 선택한 파일명이 표시된다.
- **행**: 헤더를 1행으로 센 CSV 기록 번호다. 인용된 셀 내부의 줄바꿈은 새 기록으로 세지 않으므로 텍스트 편집기의 물리 줄 번호와 다를 수 있다.
- **파일 전체**: UTF-8 해석이나 큰따옴표 구조가 깨져 기록 번호를 확정하지 못한 경우다. 0행을 수정하라는 뜻이 아니다.
- **항목**: CSV 헤더 이름이다. 필수값, 날짜·수량, 참조 ID 등을 확인한다. 헤더 오류에는 필요한 헤더 순서를 함께 표시한다.
- 오류는 파일별 필터와 20건씩 페이지 이동으로 확인한다. 서버는 현재 검증 단계에서 발견한 전체 건수와 앞 200건을 반환한다. 형식 → 참조 → 수량·날짜 관계 순서로 검사하므로 수정 후 다음 단계 오류가 나타날 수 있다.

검증 실패 시 자료는 일부도 등록되지 않는다. 파일 선택과 기준 시각은 유지되지만, 원본을 수정했다면 브라우저에서 해당 파일을 **다시 선택**하고 5종을 함께 제출한다. 오류를 무시하고 강제 등록하는 기능은 없다. 이미 성공한 자료를 다시 올리면 별도 데이터 버전이 만들어지므로 성공 여부를 먼저 확인한다.

정상 등록되더라도 제조번호 누락·출고 연결 부족은 남을 수 있다. **준비 상태 점검**에서 확인하고 근거를 확보한다. 연결 미확인 수량이 비대상이나 회수 완료를 뜻하지 않는다.

## 개발 검증 범위

합성 자료를 사용한다. 다운로드 ZIP·개별 CSV 바이트와 헤더의 일치, 빈 양식5종 등록, 메타데이터·인증, 오류200건 제한 및 전체 수, 인용 줄바꿈의 기록 번호, 잘못된 헤더·파일 파싱, 복수 파일 오류→필터→수정 재등록을 테스트한다. 실제 회사 자료의 허용 범위·정답은 별도 확인해야 한다.
