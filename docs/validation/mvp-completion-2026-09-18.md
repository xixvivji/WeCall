# 개발 MVP 마무리 — 2026-09-18

## 판단

개발·시연용 MVP는 이번 범위로 마무리할 수 있다. 원문과 데이터 등록 → 조건 추출 또는 수동 작성 → 상품 연결 검토·승인 → 판정 → 입고 증거 보완 → 대응 작업·증빙 → 종료·재개의 주요 흐름을 합성 자료로 검증했다.

**현업 인수와 운영 배포는 완료가 아니다.** 회사 자료 사용 허용 범위, 정답 검토자, 실제 담당자의 수락이 없으므로 대표 문서 검증은 합성 유형 회귀로 한정한다. 사용 시간 절감·실무 정확도·실제 회수 실적을 주장하지 않는다.

## 이번 구현

- 등록·수정·분석 화면의 UTF-8 바이트·줄 수, 분석 가능 크기 표시.
- 한도 초과 시 UI와 서버가 분석 요청을 거부하되 전체 원문 저장은 허용.
- 입력 초과·수동 검토·모델 사용 중·연결·시간 초과·응답 검증·인증·설정 문제의 구분 및 원문 확인·수동 작성 안내.
- 알려지지 않은 서비스 오류 본문 미전달, 기존 원문·분석·입력 보존, 중복 요청 방지 유지.
- [오류·입력 계약](../design/ai-failure-guidance.md).

## 대표 유형의 검증 범위

| 유형 | 근거 | 결과 |
| --- | --- | --- |
| 단일 제조번호, AND/OR, 목록, 날짜 범위 | 실제 로컬 모델 development/expanded/holdout | 기대 규칙과 판정 의미 일치 |
| 무관한 날짜, 여러 줄 | date-distractor, multiline-and 등 | 올바른 조건·원문 근거 반환 |
| 예외·취소·상충·상품별 조건 | unsupported-exclusion, withdrawn, conflicting-notice, multiple-products 등 | 수동 검토 거절 |
| 추출 불가능·명령문·불완전 날짜 | missing-condition, injection-only, missing-year 등 | 수동 검토 거절 |
| 같은 상품명·다른 규격/제조사 | recall-001 및 RecallWorkflowTests | 사람이 상품 연결·제외 사유 검토; AI 자동 매칭 아님 |
| 제조번호 누락·출고 연결 누락 | 실제 로컬 AI 업무 시연과 정답 CSV | 확인 필요 수량 유지, 임의 연결 없음 |
| 문서 정정·구버전 분석 | source-pdf/source-review, ExtractionIntegrationTests | 과거 기록 유지, 재검토·구버전 전환 차단 |
| 긴 문서·한글·이모지·줄바꿈 | ExtractionIntegrationTests, ai-guidance.spec.ts | 초과 거부, 경계 허용, 원문 보존 |

| 저장 실패·중복 요청·동시 수정 | 기존 및 추가 API/브라우저 회귀 | 입력 보존·충돌/중복 차단 |

백엔드 131개, 프론트 31개(계산·입력 단위 3개와 브라우저 28개), Python 계약·평가 35개 통과. 프론트 타입 검사·빌드와 backend bootJar 빌드 통과. 실제 Spring→FastAPI→Ollama 업무와 별도 종료·재개 HTTP 검증 통과.

## 마무리 후 남는 항목

- 실무 인수: 승인된 대표 자료와 정답표로 [인수 진행표](acceptance-guide.md)를 실제 담당자가 수행하고 수락·잔여 이슈를 기록한다. 자동 테스트 통과로 대신하지 않는다.
- 운영 전: 실제 악성 파일 검사 엔진, DB·원본 파일의 함께 복원, HTTPS·시크릿·접근 범위·모니터링·모델 자원 제한을 검증한다. 배포는 기존 요청대로 보류한다.
- 선택적 후속 기능: 작업 기한·우선순위, 상품 후보 비교, 긴 문서 분석 구간 선택. 개발 MVP 종료를 막지 않는다.
- OCR, 외부 연동, 다중 기업, 실제 회수 수량 원장은 현재 범위 밖이다.

개발 통합은 develop으로 한다. main 반영·운영 배포·실무 인수는 별도다.
