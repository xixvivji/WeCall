# 첨부 악성 파일 검사 연동

상태: 구현 및 로컬 자동 테스트 통과. 실제 검사 엔진의 설치·시그니처 갱신·운영 배치는 별도다. 기존 형식 검증과 사람의 근거 검토를 대체하지 않는다.

## 처리 계약

- `MalwareScanner`를 통해 저장할 원본 바이트를 검사한다. `clamd` 어댑터는 서버 설정 주소에 INSTREAM으로 전송한다. 사용자 파일명·경로는 전송하지 않는다.
- 업로드: 형식 검증 → 업무 권한·버전·상태 검사 → 악성 파일 검사 → 저장. 여러 파일 중 하나라도 실패하면 업무/증빙/첨부 DB 변경을 롤백하고 앞서 저장한 파일도 기존 롤백 정리로 제거한다.
- 다운로드: 사건·파일 연결 확인 → 원본 해시 확인 → 현재 엔진으로 재검사 → 반환. 기존 파일도 검사 모드가 켜져 있으면 재검사를 통과해야 한다. 검사 실패를 이유로 기존 파일을 삭제하지 않는다.
- `stream: OK`만 통과한다. 위협 탐지 422, 검사 오류·예상하지 못한 응답·시간 초과·연결 실패·동시 처리 초과는 503이다. 엔진 응답 원문과 파일 본문은 오류 메시지나 로그에 노출하지 않는다.
- 최대 동시 검사 4건, 기본 요청당 전체 시간 제한 10초(설정 100~60000ms), 응답 최대 4096바이트, 전송 청크 8192바이트. 파일별 제한이며 5개 첨부 시 최대 대기 시간은 늘어날 수 있다.
- V11: evidence_attachment에 `scan_status`, `scan_engine`, `scanned_at` 추가. 과거 파일은 `NOT_SCANNED`이다. 저장된 값은 **업로드 당시 검사 결과**로, 현재 안전 보증이나 다운로드 재검사 결과가 아니다.
- 목록 API는 `scanStatus`, `scanEngine`, `scannedAt`을 추가한다. 기존 응답 필드는 유지한다. UI는 ‘업로드 시 위협 미탐지’ 또는 ‘악성 파일 미검사’를 표시한다.

## 개발·운영 설정

`.env.example`의 다음 값을 사용한다.

| 변수 | 기본값 | 의미 |
| --- | --- | --- |
| WECALL_ATTACHMENT_SCAN_MODE | disabled | 합성 개발용; 미검사를 기록한다. 실제 파일 도입 시 clamd 사용 |
| WECALL_CLAMD_HOST | 127.0.0.1 | 회사가 승인한 검사 서버 주소 |
| WECALL_CLAMD_PORT | 3310 | 검사 서버 포트 |
| WECALL_CLAMD_TIMEOUT_MS | 10000 | 연결·쓰기·읽기를 포함한 파일별 시간 제한 |

실제 엔진이 없어도 개발을 계속할 수 있게 기본값은 disabled다. 이 모드에서 위협 미탐지라고 표시하지 않는다. mode 오타는 시작 실패로 처리한다. 서버 재시작이 설정 반영에 필요하다.

Clamd TCP는 인증·암호화를 제공하지 않으므로 공용 네트워크에 노출하면 안 된다. 사내 승인 경로나 동일 호스트로 구성해야 한다. 이 설정 자체가 회사 자료의 외부 반출 승인을 의미하지 않는다. 클라이언트가 승인되지 않은 엔진에 자동 연결하거나 공개 검사 API를 사용하지 않는다. [공식 ClamD 프로토콜](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)

운영 담당자는 서명 DB 갱신, `StreamMaxLength`/`MaxFileSize`/`MaxScanSize`가 첨부 한도와 맞는지, 제한 초과를 무검사 통과로 처리하지 않는지 확인해야 한다. 엔진의 검사 제한 탐지 설정과 정상 파일·표준 검사 샘플·중단 상황을 실제 엔진으로 검증한다. [공식 검사 안내](https://docs.clamav.net/manual/Usage/Scanning.html)

## 검증 범위

- ClamdScannerTests: 모의 TCP 서버로 청크·바이트 보존, 위협/오류/비정상 응답 차단, 연결 실패·시간 제한, disabled, 설정 오타 검증.
- AttachmentTests 추가: 두 번째 파일 검사 실패 시 전체 롤백, 검사 메타데이터, 다운로드 재검사 실패 시 본문/다운로드 이벤트 차단.
- 이 테스트의 TCP 서버는 프로토콜 모의 서버이며 실제 바이러스 탐지 엔진이 아니다. 실제 엔진 설치·서명 최신성·탐지 성능 검증은 수행하지 않았다.
