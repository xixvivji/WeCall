# 원문 변경 후 조건·판정 재검토

2026-09-18, Flyway V13. 현재 Spring/FastAPI 구조를 유지하며 업무 상태·승인·종료 검사는 Spring이 담당한다.

## 동작

조건 생성 시 사건의 현재 `source_version`을 기록한다. AI 전환도 현재 원문에 대한 작업인지 검사한 후 조건을 만든다. 판정 생성 시 그 시점의 원문 버전도 별도로 기록한다. 조건 생성 기준 버전과 판정 생성 시점 버전은 다를 수 있다.

원문이 바뀌면 조건 생성 기준과 현재 버전이 다르고 현재 버전에 대한 영향 없음 검토가 없는 조건을 재검토 필요로 표시한다. 원문이 예전 텍스트와 같아져도 새 버전이므로 다시 검토해야 한다. 기존 승인·조건 정의·과거 판정 JSON은 변경하지 않는다.

- **영향 없음:** 담당자가 현재 원문의 조건·상품 연결·기존 근거를 검토하고 사유와 확인 체크를 남긴다. 기존 근거 인용이 현재 원문에 없으면 서버가 거부한다. 인용이 남아 있다는 사실만으로 영향 없음을 자동 판단하지 않는다.
- **내용 변경:** 현재 원문 기준으로 새 조건을 작성하고 별도로 승인·판정한다. 오래된 승인 조건은 과거 기록으로 유지한다.
- **사용하지 않을 초안:** 미승인 DRAFT만 사유를 남겨 WITHDRAWN으로 철회한다. 승인 조건 철회·초안 복원은 제공하지 않는다. 새 조건을 만들 수 있다.

재검토 전 조건 승인·새 판정을 차단한다. 입고 증거 승인도 기준 판정의 조건 재검토가 해결돼야 새 데이터·조건으로 복제할 수 있다. 증거 자체의 제출·조회·거절은 가능하다.

## 종료와 화면

종료는 **최신 비철회 조건과 선택한 판정의 조건**을 각각 확인한다. 하나라도 재검토가 필요하면 `SOURCE_REVIEW_REQUIRED`로 차단한다. 모든 과거 승인 조건을 무조건 재검토하도록 요구하지 않는다. 새 승인 조건·새 판정을 선택하면 과거 승인 기록을 유지하면서 종료를 진행할 수 있다. 미승인 초안은 기존 PENDING_CONDITIONS로 계속 차단하며 불필요한 것은 철회해야 한다.

종료 스냅샷은 현재 원문 버전, 선택 판정 생성 당시 원문 버전, 조건의 기준 버전과 재검토 기록을 포함한다. 영향 없음 확인 뒤 기존 판정을 종료 기준으로 쓸 수 있지만 그 판정의 원문 버전·수량을 현재 것으로 덮어쓰지 않는다. 사건 종료 후 검토·철회는 차단하며 먼저 재개해야 한다.

- 조건 카드: 생성 기준/현재 원문 버전, 재검토 안내, 영향 없음 확인 이력, 초안 철회 사유.
- 다음 할 일·종료 점검: 재검토 차단 항목과 조건 검토 화면 연결.
- 대시보드: sourceReviewCases는 진행 중 사건 중 재검토가 필요한 초안 또는 최신 비철회 조건이 있는 사건 수. 기존 수량 확인 필요 사건과 별도다.
- 검토 대기함: DRAFT는 기존 CONDITION에 포함. 최신 비철회 승인 조건의 재검토는 SOURCE 항목으로 제공한다. 같은 초안을 두 항목으로 중복 집계하지 않는다.
- 보고서: 현재 원문·판정 당시 버전·선택 조건 재검토 상태와 검토 근거 표시.
- 업무 이력: 조건 영향 없음 확인·초안 철회 기록과 조건 상세 링크 제공.

## API

두 변경 API는 REVIEWER 세션·CSRF가 필요하다. 사건 잠금 → 조건 잠금 순서를 유지하고 `expectedSourceVersion`이 다르면 409를 반환한다. 종료·다른 사건·중복 검토·잘못된 상태도 차단한다.

| POST 경로 | 본문 | 결과 |
| --- | --- | --- |
| `/api/v1/recalls/{caseId}/conditions/{conditionId}/source-review` | `{expectedSourceVersion, note, unchangedConfirmed:true}` | 현재 원문 버전의 영향 없음 기록·검토 상태 |
| `/api/v1/recalls/{caseId}/conditions/{conditionId}/withdrawal` | `{expectedSourceVersion, note}` | 철회된 초안·행위자·사유 |

조건 조회의 `sourceReview`는 `{basisVersion,currentVersion,required,reviews}`다. `reviews`는 원문 버전별 검토자·사유·시각을 포함한다. 검토자·철회자는 세션에서 결정한다. API 호출자가 지정하지 않는다. 검토는 조건 승인과 별개이며 DRAFT를 자동 승인하지 않는다.

## 이관과 한계

과거 조건·판정은 기준 원문 버전의 확실한 기록이 없어 NULL로 이전한다. 현재 원문에 임의 연결하지 않는다. 오래된 승인 조건은 운영자가 확인 후 영향 없음 검토를 남기거나 새 조건으로 대체해야 한다. 이미 종료된 사건의 기존 종료 스냅샷은 변경하지 않는다.

V13의 `condition_source_review`는 조건+사건 및 원문 버전 FK로 연결된다. `condition_source_state`는 조회용 뷰이며 현재 원문과 검토 이력으로 상태를 계산한다. 조건·판정의 최초 source_version은 양수 CHECK이며 별도 원문 FK는 아니다. 모든 재검토가 문서 의미까지 자동 검증되는 것은 아니다. 사람의 판단과 근거 기록이 필요하다.
