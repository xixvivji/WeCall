# 사건별 대응 결과 보고서

사건 상세 → **대응 보고서**에서 기준 판정을 선택하고 **인쇄 · PDF 저장**을 누른다. 인쇄 창에서 PDF로 저장한다. 승인 조건·상품 연결·판정 수량과 현재 업무 현황을 구분해 검토·공유하기 위한 화면이다.

## 조회 계약

`GET /api/v1/recalls/{caseId}/report?assessmentId={uuid}`

- 기존 사건 조회 권한과 동일하게 REVIEWER·OPERATOR가 조회할 수 있다. 익명 401, 없는 사건·다른 사건 판정 404, 잘못된 UUID 400.
- `assessmentId` 생략 시 사건·업무 현황만 제공한다. 임의로 최신 판정을 선택하거나 수량을 0으로 만들지 않는다.
- PostgreSQL REPEATABLE_READ 읽기 트랜잭션 하나에서 사건·판정·조건·작업·증빙·종료 점검·종료/재개 기록을 조회한다. `generatedAt`은 트랜잭션 시작 시각이며, 모든 현황은 같은 DB 스냅샷을 사용한다.
- `Cache-Control: no-store`. 저장된 보고서 ID나 별도 보관 테이블은 없다. 새로 조회하면 최신 업무 현황으로 바뀐다.
- `case`, `assessment`, `condition`, `generatedAt`, `assessmentCreatedAt`, `datasetAsOf`, `tasks`, `proofs`, `evidence`, `blockers`, `warnings`, `lifecycle` 필드를 제공한다.
- 판정이 없으면 assessment/condition/assessmentCreatedAt/datasetAsOf는 null이다.
- 업무는 사건의 전체 작업을 제공한다. 선택 판정·다른 판정·사건 단위 작업을 화면에서 명시한다. 증빙은 이전 회차도 포함하고 현재 회차와 구분한다.
- 증빙 원문·첨부 바이너리·종료 당시 내부 스냅샷은 요약 응답에 포함하지 않는다. 검토 결과·검토자·의견·시각과 원본 식별자를 제공한다. 사건 원문과 승인 조건 근거는 보고서에 포함한다.

## 해석과 인쇄

- 판정의 대상/비대상/확인 필요는 EA, 작업 상태는 건수다. 작업 완료를 실제 회수 수량으로 환산하지 않는다.
- 출고 연결 미확인 수량은 확인 필요에 포함되어 있으므로 더하지 않는다.
- 종료된 사건도 보고서를 조회할 수 있다. 종료 점검은 조회 시점의 점검이며, 종료 당시 승인 기록을 대신하지 않는다. 종료/재개 이력에서 당시 기준 판정과 사유를 확인한다.
- 인쇄는 현재 화면에 로드된 보고서를 사용한다. 조회 실패/재조회 중에는 이전 내용을 제거하고 인쇄 버튼을 비활성화한다. 판정 변경 시 이전 요청이 늦게 도착해도 덮어쓰지 않는다.
- 인쇄 CSS는 메뉴·탭·버튼을 숨기고 A4 여백, 표 너비, 줄바꿈을 적용한다. 브라우저에서 PDF 저장 위치와 머리글·바닥글 옵션을 선택한다. 서버 PDF 생성·자동 발송은 하지 않는다.
- 전체 업무 목록을 출력하므로 대규모 사건은 보고서가 길어질 수 있다. 목록을 임의로 잘라서 완료 현황을 누락하지 않는다.

## 검증

- RecallWorkflowTests: 선택한 과거 판정 유지, 다른 판정 작업 포함, 현재/이전 증빙 회차 구분, 미해결 항목, 무판정, 종료 사건 조회, 역할·사건 범위·UUID 오류·캐시 정책.
- report.spec.ts: 실제 CSV 등록부터 승인/판정/작업 생성 후 보고서, 무판정 전환, 오류/재시도, HTML 문자 이스케이프, 날짜 표시, 모바일 너비와 인쇄용 메뉴 숨김/버튼 호출 확인.
- 합성 데이터 검증이며 실사용 고객의 서식 승인이나 실제 회수 완료 확인을 뜻하지 않는다.
