# 입력 보호와 사건별 다음 할 일

## 미저장 입력 보호

대상: 사건 등록, 조건 초안, 입고 증거 제안·검토 의견, 대응 작업 등록·배정/상태 변경 의견·처리 증빙과 첨부, 종료/재개 기록, CSV 등록 시각·파일 선택.

- 탭·기준 판정 변경, 메뉴 이동, 브라우저 뒤로/앞으로 이동, 로그아웃 시 미저장 입력이 있으면 버릴지 확인한다. 취소하면 현재 입력·선택한 파일을 유지한다.
- 새로고침/탭 닫기는 브라우저 기본 beforeunload 확인을 사용한다. 문구는 브라우저가 결정하며, 브라우저 강제 종료·기기 종료까지 복구를 보장하지 않는다.
- 등록 폼 닫기·다른 작업 상세 선택에도 확인을 적용한다. 닫기를 승인하면 해당 폼의 입력을 비운다.
- 성공 응답을 받은 필드만 저장 기준으로 갱신한다. 실패 응답이나 네트워크 오류에서는 입력·파일 선택을 지우지 않는다. 작업 증빙 제출과 다른 작업 변경은 별도로 추적하여 다른 폼의 작성 내용을 지우지 않는다.
- 기준 판정 변경 확인을 취소하면 드롭다운과 실제 화면의 판정이 일치하도록 원래 선택을 유지한다. 보완 후 판정 열기도 이동 승인 전 현재 입력을 초기화하지 않는다.
- 브라우저 저장소(localStorage/IndexedDB 등)나 서버에 초안을 자동 저장하지 않는다. 본문과 파일은 현재 화면 메모리에만 있다. 이동·새로고침을 승인하면 미저장 내용은 사라진다.
- 검색·필터·읽기 전용 조회는 초안으로 취급하지 않는다. 계정 관리·비밀번호 폼의 자동 저장/복원은 이번 범위가 아니다. 인증 만료로 로그아웃된 내용은 복구하지 않는다.

구현: drafts.ts의 폼별 상태 비교, router.beforeEach, beforeunload. 성공/실패 경로와 컴포넌트 수명에 맞춰 등록·해제한다. 폼의 파일 선택은 파일명·크기·수정 시각·타입으로 비교하며 파일 내용을 복제·업로드하지 않는다.

## 다음 할 일

사건의 ‘원문 · 조건 검토’ 탭에 표시한다. 기존 `/api/v1/recalls/{caseId}/closure-check` 응답을 기준으로 한다. 새 API나 스키마를 만들지 않았다.

- 조건 없음 → 첫 조건 작성(검토자).
- 미승인 조건 → 해당 조건 검토 위치.
- 기준 판정 없음·이전 조건 판정 → 승인 조건과 판정 확인.
- 확인 필요 입고·출고 → 증거 보완·영향 조회.
- 미처리 작업·미검토 입고 증거·처리 증빙 → 대응 작업·입고 증거 화면.
- 차단 항목이 없으면 실제 대응 범위를 사람이 확인하도록 최종 종료 점검을 안내한다. 자동 종료하거나 업무 완료로 단정하지 않는다.
- 취소 작업·다른 판정 작업·사건 단위 작업은 추가 검토 사항으로 표시한다.
- 종료된 사건은 보고서와 종료 이력/재개 검토로 안내한다.

입고·작업·증빙은 건수, 출고 확인 필요는 EA다. 대상 수량을 작업 건수로 바꾸거나 여러 차단 사유를 더해 ‘총 미완료 건수’로 표시하지 않는다. 실행 담당자는 기존 읽기 권한으로 확인하고, 승인·검토·종료는 검토자의 업무임을 명시한다.

조회 실패 시 이전 할 일 목록을 숨기고 재시도 버튼을 표시한다. 조건 저장/승인, 판정 변경, 탭 재진입 또는 ‘다시 확인’으로 현재 상태를 읽는다. 자동 실시간 동기화나 고객 알림 발송은 포함하지 않는다.

## 검증

drafts-guidance.spec.ts에서 실제 새로고침 확인 취소, 이동/닫기 취소, 명시적 입력 폐기, 저장 실패/성공, 첨부 검사 422 후 입력·선택 파일 보존 및 재제출, 서버의 조건 승인/판정 상태에 따른 안내 변경, 안내 조회 오류 복구, 역할 안내와 모바일 너비를 확인한다. 기존 전체 업무 시나리오로 보완 판정 이동과 증빙/종료 흐름을 함께 검증한다.
