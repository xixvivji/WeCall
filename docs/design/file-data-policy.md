# 파일·데이터 관리 기준과 첨부 구현안

상태: 2026-09-17 로컬 첨부·원문 PDF 보관 V12 반영·운영 정책 초안. 실제 고객사의 정책·보관 기간·삭제 승인자를 확정한 문서가 아니다. 아래 표는 로컬 구현 기준과 미확정 운영 결정을 구분한다. 구현 계약은 [첨부 API](attachments-api.md)와 [원문 PDF·수정 이력](source-pdf.md)을 따른다.

## 현재 구현

업무 텍스트·정규화된 CSV 행·판정·감사 이력은 PostgreSQL에 보존한다. CSV 원본은 메타데이터만 남는다. 새 입고 증거·작업 증빙의 PDF·PNG·JPEG 첨부 저장소와 인증 다운로드를 구현했다. Clamd 검사 어댑터와 실패 차단을 추가했다. 기본 합성 개발 모드는 미검사로 기록하며 실제 검사 엔진 배치, 보관 만료·파기, 백업 자동화는 별도다. [검사 계약](attachment-scanning.md) 프로젝트는 문서 추론에 외부 모델 API를 사용하지 않는 로컬 처리를 선택했다. 실제 회사 자료의 허용 범위·운영 정책 승인은 별도다.

사건 등록 시 텍스트 PDF 원본도 같은 파일 저장소에 보관한다. 서버 추출본·사람이 확인한 원문과 수정 이력은 DB에 저장한다. 미리보기만 수행하면 영구 파일을 만들지 않는다. 기존 미보관 PDF를 소급 복원하지 않는다.

## 로컬 개발 기준

| 항목 | 로컬 구현 | 운영 시 결정할 사항 |
| --- | --- | --- |
| 저장 방식 | Storage 인터페이스 + 로컬 파일 어댑터; Git과 공개 웹 경로 밖의 전용 디렉터리 | 사내 저장소 또는 승인 클라우드, 지역·계정·관리 주체 |
| 파일 범위 | 증거·증빙: PDF/PNG/JPEG 파일당 10 MiB·최대 5개; 사건 원문: PDF 1개·10 MiB·50쪽 | 현업 파일 크기·건수 요구 |
| 파일명 | 사용자 파일명은 표시 메타데이터만; 저장 키는 서버 생성 UUID | 표시 파일명의 민감 정보 처리 |
| 검사 | 확장자·실제 형식·크기 확인, 경로 조작·빈 파일·허용 외 형식 거부 | 검사 엔진·격리 환경; 형식 검사만으로 악성 여부를 보장하지 않음 |
| 미리보기 | 바이너리는 attachment 다운로드; 사건 원문 PDF는 추출 텍스트 미리보기 제공 | 보안 검토 후 격리된 미리보기·OCR 도입 |
| 원문 | 바이트 변경 없이 보존, SHA-256·크기·등록자·시각 기록 | 암호화·키 관리·백업 위치 |
| 삭제 | 승인 근거에 연결된 파일의 일반 삭제 API를 초기 구현에서 제공하지 않음 | 보관 기간, 법적 보존 필요, 파기 승인·유예·증명 |
| 외부 전송 | 로컬 합성 파일로 개발; 외부 OCR·모델 API 호출 없음; 로컬 FastAPI/Ollama 사용; clamd 모드에서만 설정된 검사 서버로 바이트 전송 | 승인된 전송 목적·필드·지역·보존 조건 |

10 MiB와 5개 제한은 기존 CSV 제한을 바꾸는 결정이 아니다. 원본 CSV 영구 보관도 이 첨부 기능과 별도로 범위를 정한다. 무기한 운영 보관을 확정하지 않는다.

## 업무별 권한·연결

- 기존 세션 인증·CSRF와 사건 접근 권한을 그대로 적용한다. 저장 경로나 객체 키만 알아도 다운로드되는 공개 URL은 만들지 않는다.
- 검토자는 진행 중 사건의 근거를 등록하고 검토한다. 실행 담당자는 입고 증거 제안과 본인 담당 작업의 증빙 생성 범위에서 첨부한다.
- 파일 등록자만으로 연결 권한을 판단하지 않고 대상 사건·증거·작업 및 현재 상태를 서버에서 다시 검사한다.
- 승인·반려가 끝난 근거의 첨부를 교체하거나 추가하지 않는다. 수정이 필요하면 새로운 제안/증빙으로 이력을 남긴다.
- 파일을 첨부했다고 사실이 승인되는 것은 아니다. 상품·입고·수량·제조분 확인은 기존 사람의 검토를 유지한다.
- 다운로드는 현재의 단일 기업 조회 정책을 따른다. 사용자별 문서 제한이 필요하면 실제 자료 투입 전에 별도로 설계한다.

## 저장 실패와 무결성 설계

파일은 검증 후 임시 파일에 기록하고 원자 이동하며, 메타데이터·업무 연결은 같은 DB 트랜잭션으로 커밋한다. 롤백이면 파일을 삭제한다. 커밋된 파일만 다운로드하며 매번 크기·해시를 확인한다. 강제 종료 후 고아 파일은 백엔드 정지 상태에서 로컬 점검 스크립트로 처리한다. [실패 복구 절차](attachments-api.md)

원문 PDF는 V12의 source_document·source_document_event, 검토·수정 텍스트는 source_revision에 기록한다. 원문 수정 시 원본 바이트·서버 추출본은 바꾸지 않는다. 정리 도구는 source_document와 evidence_attachment 참조를 모두 조회하며 DB 조회가 실패하면 삭제하지 않는다.

V10의 evidence_attachment가 사건·입고 증거 또는 작업·증빙을 FK로 연결한다. 첨부는 생성 때만 연결되며 이후 변경 API는 없다. attachment_event에 UPLOADED·DOWNLOAD_REQUESTED 행위자와 시각을 남긴다. 다운로드 완료를 보장하는 이력은 아니다. 파일 본문·비밀번호·토큰을 감사 이력에 저장하지 않는다.

## 실제 자료 도입 전에 받아야 할 결정

| 결정 | 확인할 사람/역할 | 현재 상태 |
| --- | --- | --- |
| 허용 자료 등급·개인정보·거래정보 범위 | 자료 제공 책임자·보안 담당 | 미정 |
| 저장 위치와 접근 범위 | 운영·보안 담당 | 미정 |
| 보관 기간·삭제 승인·보존 예외 | 업무 책임자·회사 정책 담당 | 미정 |
| 백업 주기·복구 목표·복원 시험 | 운영 담당 | 미정 |
| 외부 통신·AI/OCR·검사 서비스 허용 | 보안·계약 담당 | 미정 |

이 표는 회사의 실제 조직이나 법정 보관 의무를 단정하지 않는다. 결정 전에는 합성 자료로 기능을 검증하고 실제 회사 자료 도입을 보류한다. [자료 준비 양식](../validation/materials-checklist.md)에 결정 근거와 사용 범위를 기록한다.

## 첨부 기능 인수 기준

허용 파일 업로드·인가된 다운로드, 미인증/권한 없음 차단, 사건 간 연결 오류 차단, 위장 확장자·경로 조작·용량 초과 거부, 승인된 근거 교체 차단, 원본 해시 일치, 원문 수정자·사유·버전 충돌, 저장/DB 실패 및 고아 파일 복구, 민감 정보 로그 배제, 모바일 생성·조회 흐름을 테스트한다. AttachmentTests·브라우저 테스트와 정리 스크립트 테스트로 기능을 검증했다. 실제 검사 엔진의 탐지 검증·서명 갱신·복원 훈련은 별도다.
