# 파일·데이터 관리 기준과 첨부 구현안

상태: 2026-09-13 기술 초안. 실제 고객사의 정책·보관 기간·삭제 승인자를 확정한 문서가 아니다. 아래 개발 제안은 합성 자료로 다음 기능을 만들기 위한 기준이다.

## 현재 구현

업무 텍스트·정규화된 CSV 행·판정·감사 이력은 PostgreSQL에 보존한다. CSV 원본은 메타데이터만 남는다. PDF·이미지 첨부 저장소, 악성 파일 검사, 파일 다운로드 API, 보관 만료·파기, 백업 자동화는 미구현이다. 회사 문서의 외부 반출 허용 여부는 아직 전달받지 않았다.

## 로컬 개발용 제안

| 항목 | 다음 구현의 제안 | 운영 시 결정할 사항 |
| --- | --- | --- |
| 저장 방식 | Storage 인터페이스 + 로컬 파일 어댑터; Git과 공개 웹 경로 밖의 전용 디렉터리 | 사내 저장소 또는 승인 클라우드, 지역·계정·관리 주체 |
| 파일 범위 | PDF, PNG, JPEG; 파일당 10 MiB, 증거당 5개를 초기 제한으로 제안 | 현업 파일 크기·건수 요구 |
| 파일명 | 사용자 파일명은 표시 메타데이터만; 저장 키는 서버 생성 UUID | 표시 파일명의 민감 정보 처리 |
| 검사 | 확장자·실제 형식·크기 확인, 경로 조작·빈 파일·허용 외 형식 거부 | 검사 엔진·격리 환경; 형식 검사만으로 악성 여부를 보장하지 않음 |
| 미리보기 | 초기에는 inline 렌더링 없이 attachment 다운로드 | 보안 검토 후 격리된 미리보기·OCR 도입 |
| 원문 | 바이트 변경 없이 보존, SHA-256·크기·등록자·시각 기록 | 암호화·키 관리·백업 위치 |
| 삭제 | 승인 근거에 연결된 파일의 일반 삭제 API를 초기 구현에서 제공하지 않음 | 보관 기간, 법적 보존 필요, 파기 승인·유예·증명 |
| 외부 전송 | 로컬 합성 파일로 개발; 외부 OCR·AI·검사 서비스 호출하지 않음 | 승인된 전송 목적·필드·지역·보존 조건 |

10 MiB와 5개 제한은 기존 CSV 제한을 바꾸는 결정이 아니다. 원본 CSV 영구 보관도 이 첨부 기능과 별도로 범위를 정한다. 무기한 운영 보관을 확정하지 않는다.

## 업무별 권한·연결 제안

- 기존 세션 인증·CSRF와 사건 접근 권한을 그대로 적용한다. 저장 경로나 객체 키만 알아도 다운로드되는 공개 URL은 만들지 않는다.
- 검토자는 진행 중 사건의 근거를 등록하고 검토한다. 실행 담당자는 입고 증거 제안과 본인 담당 작업의 증빙 생성 범위에서 첨부한다.
- 파일 등록자만으로 연결 권한을 판단하지 않고 대상 사건·증거·작업 및 현재 상태를 서버에서 다시 검사한다.
- 승인·반려가 끝난 근거의 첨부를 교체하거나 추가하지 않는다. 수정이 필요하면 새로운 제안/증빙으로 이력을 남긴다.
- 파일을 첨부했다고 사실이 승인되는 것은 아니다. 상품·입고·수량·제조분 확인은 기존 사람의 검토를 유지한다.
- 다운로드는 현재의 단일 기업 조회 정책을 따른다는 제안이다. 사용자별 문서 제한이 필요하면 실제 자료 투입 전에 별도로 설계한다.

## 저장 실패와 무결성 설계

파일 시스템과 DB는 같은 트랜잭션이 아니다. 구현 시 파일 임시 저장 → 형식·크기·해시 검증 → 업무 메타데이터·연결 등록 → 사용 가능 상태 전환을 설계하고 중간 실패를 테스트해야 한다. 완료 상태가 아닌 파일은 다운로드하지 못하게 한다. 고아 파일 정리 절차와 실행 중 파일을 잘못 지우지 않는 기준도 필요하다.

최소 메타데이터 제안: id, 저장 키, 표시 파일명, 형식, 크기, SHA-256, 등록자·시각, 상태. 업무 연결은 대상 유형/ID를 문자열 하나로만 기록하기보다 실제 FK와 사건 경계를 검증할 수 있게 설계한다. DB 마이그레이션과 API 명세는 첨부 구현 작업에서 확정한다. 업로드·연결·다운로드·관리 삭제 이력을 남기되 파일 본문·비밀번호·토큰은 로그에 쓰지 않는다.

## 실제 자료 도입 전에 받아야 할 결정

| 결정 | 확인할 사람/역할 | 현재 상태 |
| --- | --- | --- |
| 허용 자료 등급·개인정보·거래정보 범위 | 자료 제공 책임자·보안 담당 | 미정 |
| 저장 위치와 접근 범위 | 운영·보안 담당 | 미정 |
| 보관 기간·삭제 승인·보존 예외 | 업무 책임자·회사 정책 담당 | 미정 |
| 백업 주기·복구 목표·복원 시험 | 운영 담당 | 미정 |
| 외부 통신·AI/OCR·검사 서비스 허용 | 보안·계약 담당 | 미정 |

이 표는 회사의 실제 조직이나 법정 보관 의무를 단정하지 않는다. 결정 전에는 합성 자료로 기능을 검증하고 실제 회사 자료 도입을 보류한다. [자료 준비 양식](../validation/materials-checklist.md)에 결정 근거와 사용 범위를 기록한다.

## 첨부 기능 인수 기준

허용 파일 업로드·인가된 다운로드, 미인증/권한 없음 차단, 사건 간 연결 오류 차단, 위장 확장자·경로 조작·용량 초과 거부, 승인된 근거 교체 차단, 원본 해시 일치, 저장/DB 실패 및 고아 파일 복구, 민감 정보 로그 배제, 모바일 생성·조회 흐름을 테스트한다. 이 기준은 아직 통과한 테스트 목록이 아니다.
