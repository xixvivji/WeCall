# AI 데이터 처리 경계

## 설계 방향과 미확정 사항

회사 내부 자료가 모두 일률적으로 외부 반출 금지라고 단정할 수는 없다. 실제 고객사의 보안 정책, 자료 등급, 계약과 개인정보 처리 조건을 확인해야 한다. 현재는 고객사 정책을 전달받지 않았으며 실제 외부 AI 공급자도 선정하지 않았다.

WeCall은 승인되지 않은 외부 전송을 하지 않는 방향으로 설계한다. 이는 설계 원칙이며, 지금 네트워크 차원의 반출 차단이 구현됐다는 의미는 아니다. 모델 연결 전에 고객사가 요구하는 경계가 물리적 사내망인지, 승인된 클라우드 환경까지 포함하는지 확정해야 한다.

## 현재 코드의 데이터 흐름

- Spring Boot는 회수 사건의 `sourceText`와 작업 ID를 설정된 FastAPI `/v1/extractions`로 보낸다. 재고·출고 DB 전체를 보내지 않는다.
- 기본 주소는 `http://127.0.0.1:8000`이다. `WECALL_AI_BASE_URL`은 운영자가 변경할 수 있어 현재 코드만으로 내부망 주소를 강제하지 않는다.
- FastAPI provider 기본값은 `disabled`다. 현재 구현한 `fixture`는 합성 샘플에 대한 고정 응답이며 외부 모델 API를 호출하지 않는다.
- `ollama-local`은 고정 루프백 주소의 Ollama Qwen3 4B Instruct를 호출한다. 환경 프록시·리다이렉트·원격 모델 정보를 차단하며 전용 실행 도구는 Ollama 클라우드 기능을 끈다. [구현과 제한](local-ai.md)을 따른다.
- 외부 모델 API, OCR, 외부 임베딩, 외부 벡터 DB는 연결하지 않았다.
- 원문과 추출 응답은 PostgreSQL에 보존한다. DB·로그·백업·모니터링 저장 위치도 향후 보안 경계에 포함해야 한다.
- 서비스 토큰은 호출자 인증용이다. 데이터 전송 목적지를 제한하거나 외부 반출을 차단하는 기능이 아니다.

## FastAPI와 외부 전송의 관계

FastAPI를 사내에서 실행하더라도 그 코드가 외부 모델 API를 호출하면 입력 내용은 외부로 전달된다. 공급자가 학습에 사용하지 않는다는 조건, 저장하지 않는다는 조건, 외부 전송 자체가 없다는 조건은 각각 다르다.

RAG도 자동으로 내부 처리가 되는 것은 아니다. 원문을 외부 임베딩 서비스에 보내거나 검색한 문단을 외부 LLM에 전달하면 해당 정보는 경계 밖으로 나간다. 문서의 개인정보를 가려도 단가·물량·거래처 관계 같은 기밀 업무 정보가 남을 수 있다.

## 반출 금지가 요구되는 경우의 목표 구조

`내부 사용자 → 내부 Spring Boot / PostgreSQL → 내부 FastAPI → 내부 모델·OCR·임베딩`

모델 파일 도입 및 업데이트 절차와 추론 중 데이터 통신을 구분한다. 실행 환경의 외부 통신을 기본 차단하고 필요한 내부 목적지만 허용한다. 텔레메트리·오류 추적·로그·백업에도 원문이 무심코 전달되지 않도록 구성하고 검증해야 한다. 이 네트워크·운영 통제는 아직 구현하지 않았다.

공개 회수 공고와 합성 문서만으로 먼저 품질을 검증한다. 실제 회사 문서, 거래처·입고·출고 데이터와 인증 정보는 소스 저장소나 테스트 fixture에 넣지 않는다. 프라이빗 Git 저장소도 회사가 승인한 보관 경계인지 별도 확인해야 한다.

외부 API를 허용하는 경우에는 전송 필드, 목적, 보존 기간·지역, 학습 사용 여부, 하위 처리자와 접근 권한을 승인 범위에 맞춰 정하고 최소한의 정보만 보낸다. 이 문서는 회사 승인이나 법률 검토를 대신하지 않는다.

참고: [OWASP LLM02:2025 Sensitive Information Disclosure](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/) — 기밀 업무 정보와 개인정보 노출 위험 및 정보 접근·처리 통제.
