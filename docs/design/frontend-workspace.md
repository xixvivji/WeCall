# Vue 업무 화면과 조회 API

프론트는 Vue 3 + TypeScript + Vite로 구현했다. 버전은 `frontend/package-lock.json`으로 고정하며 Node.js 24를 기준으로 검증한다. TypeScript는 vue-tsc와 호환되는 5.9.3을 사용한다.

## 로컬 실행

저장소 루트에서 기존 `.env` 계정 설정과 PostgreSQL을 준비한 후 백엔드를 실행한다.

```sh
set -a
source .env
set +a
docker compose up -d postgres
./backend/gradlew -p backend bootRun
```

다른 터미널에서:

```sh
cd frontend
npm ci
npm run dev
```

`http://127.0.0.1:5173/`에서 기존 계정으로 로그인한다. Vite는 `/api`를 `http://127.0.0.1:8080`으로 전달한다. 세션 쿠키·CSRF 보호를 그대로 사용하며 브라우저에 비밀번호·세션 토큰을 로컬 저장하지 않는다. 로그인 후 CSRF 토큰을 새로 가져온다. API 인증이 만료되면 로그인 화면으로 돌아간다. 실제 데이터 변경은 서버 권한 검사를 거친다.

프론트 환경변수에 서비스 토큰이나 DB 비밀번호를 넣지 않는다. 이 구성은 로컬 개발용이며 운영 배포는 아직 하지 않았다. 배포 시 동일 출처의 프론트·API 라우팅과 HTTPS를 구성해야 한다.

## 구현 범위

- 로그인·로그아웃, 세션 복원, 검토자와 실행 담당자별 버튼·API 권한
- 사건명 검색, 상태·출처 필터, 페이지 조회, 사건 생성·원문 상세
- CSV 5종 업로드·검증 오류 표시, 데이터 버전과 상품 페이지 조회
- 수동 조건 편집: 같음·목록·범위·AND/OR, 원문 인용, 상품별 연결 확인·제외와 검토 근거
- 조건 버전 확인 → 체크 후 승인 → 별도 판정 실행
- 판정 이력 선택, 재고·출고 대상/비대상/확인 필요와 미연결 수량 표시
- 사건·재고·출고별 대응 작업 생성, 활성 계정 배정, 시작·증빙 제출·승인/반려·완료·재개·취소, 이력 조회
- 종료 점검 차단·주의 항목 확인, 대응 범위 확인 후 종료, 사유를 기록한 재개

대상 판정, 상품 연결과 조치 상태는 분리한다. 미검토 상품을 자동 제외하지 않으며 연결 없는 출고는 추정하지 않는다. 조건 초안을 저장한 뒤에 별도 승인이 필요하다. 과거 판정과 데이터 스냅샷을 유지한다.

입고 증거 등록·목록·비교·반려·승인·재판정 화면과 검토자용 계정 생성·목록 화면을 제공한다. 증거 승인은 기존 데이터와 판정을 보존한 채 새 버전을 만든다. 계정 관리에서 사유를 남겨 비활성화·재활성화하고 최근 변경 이력을 조회한다. 두 역할 모두 내 계정에서 본인 비밀번호를 변경하며 이후 다시 로그인한다. AI 추출 검토 전용 화면은 후속 범위이며 프론트에서 AI 모델을 호출하지 않는다.

## 추가 조회 API

모두 로그인 후 REVIEWER와 OPERATOR가 사용할 수 있다.

| 경로 | 쿼리 | 응답 |
| --- | --- | --- |
| GET `/api/v1/recalls` | q, status, sourceType, page, size | 사건 목록과 미승인 조건 수·남은 작업 수 |
| GET `/api/v1/recalls/{id}/assessments` | 없음 | 최신순 판정 ID·조건 ID·데이터 ID·생성 시각 |
| GET `/api/v1/datasets` | page, size | 데이터 ID·기준 시각·등록 시각 |
| GET `/api/v1/datasets/{id}/products` | q, page, size | 상품 ID·이름·제조사·규격·단위 |

페이지 응답은 `items`, `page`, `size`, `totalElements`, `totalPages`를 포함한다. page는 0부터 시작하며 size 기본 20, 허용 1~100이다. 사건명 q는 최대 200자, 대소문자를 구분하지 않는 리터럴 부분 검색이다. `%`, `_`는 와일드카드가 아니다. 상품 검색은 상품명 또는 ID를 검색한다.

사건 목록은 생성 시각 내림차순, 동일 시각에서는 ID 내림차순이다. status는 OPEN/CLOSED, sourceType은 SUPPLIER/OFFICIAL/INTERNAL이며 빈 값은 전체 조회다. 잘못된 범위·형식은 400, 없는 사건·데이터는 404다. 목록 수와 결과는 같은 읽기 트랜잭션에서 조회한다.

## 검증

```sh
./backend/gradlew -p backend test bootJar
cd frontend
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E는 실행 중인 로컬 프론트·백엔드·PostgreSQL과 `.env`의 검토자·실행 담당자 계정이 필요하다. 테스트마다 합성 데이터와 사건을 새로 등록하며 기존 데이터를 지우지 않는다. 계정 비밀번호·브라우저 trace는 테스트 결과에 저장하지 않는다. 테스트 화면 캡처는 `/tmp`에만 저장한다.

선택적 WebMCP가 있는 브라우저에서는 현재 화면의 사건 목록을 읽는 `get_visible_recall_cases`만 등록한다. 지원하지 않는 브라우저에는 영향이 없다. 데이터 변경 기능은 노출하지 않는다.

검증 결과: 백엔드 73개 테스트, Vue 타입 검사·프로덕션 빌드, 실제 서버를 사용하는 브라우저 E2E 3개를 통과했다. 데스크톱·모바일 캡처를 확인했다. 사용한 일반 Chromium에는 WebMCP가 없어 실제 표준 컨텍스트 검증은 수행하지 못했다.

## 증거 목록과 계정 화면

GET `/api/v1/recalls/{caseId}/evidence`는 `status`(빈 값/PENDING/APPROVED/REJECTED), `page`(0부터), `size`(기본 20, 최대 100)로 조회한다. 목록은 원문을 제외한 요약이며 상세를 열 때 원문·기존 사실·제안을 조회한다. 검토자와 실행 담당자가 조회·등록할 수 있고 승인·반려는 검토자만 수행한다. CLOSED 사건에는 변경 버튼을 표시하지 않는다.

`/#/users`의 계정 생성과 목록은 REVIEWER만 사용한다. 초기 역할은 OPERATOR이며 REVIEWER 권한의 범위를 표시한다. 비밀번호는 생성 요청이 끝나면 성공·실패와 무관하게 입력 상태에서 지운다. 기존 서버의 bcrypt 저장·중복 계정 검사·UTF-8 바이트 제한을 그대로 사용한다.

## 업무 대시보드

`/#/workspace`에 사건 현황과 내 할 일을 제공한다. 검토자는 전체 작업과 재배정 필요 작업을 조회할 수 있다. 상태·사건명·작업명 필터와 페이지 이동을 제공하며 작업 열기로 기존 사건의 해당 작업 상세에 바로 진입한다. 집계 정의와 권한은 [workspace-api.md](workspace-api.md)를 따른다.

## 판정 CSV

영향 조회의 재고 CSV 다운로드·출고 CSV 다운로드 버튼은 현재 선택한 저장 판정 ID를 고정해 요청한다. 이전 판정을 선택하면 이전 결과를 반환한다. 실패 시 오류를 표시하며 인증 만료 시 로그인 화면으로 돌아간다. 파일에는 판정·조건·데이터 ID를 포함한다. 자세한 형식은 [recall-api.md](recall-api.md)를 따른다.

## 데이터 준비 상태

데이터 관리 목록의 준비 상태 점검은 `/datasets/{id}/readiness`로 이동한다. 버전별 건수·입고 누락·출고 연결 요약과 문제 기록의 페이지 목록을 제공하며 두 역할 모두 조회할 수 있다. 회수 대상 판정과 데이터 누락 점검을 구분한다. API 및 집계 기준은 [csv-import.md](csv-import.md)를 따른다.

## 판정 결과 비교

사건 상세의 판정 비교 탭에서 서로 다른 저장 판정 두 개를 선택한다. 기본 선택은 목록의 최근 판정과 직전 판정이며 실행 버튼으로 비교한다. 기준·비교 순서는 사용자가 결정하며 증감은 비교에서 기준을 뺀 값이다.

재고·출고별 대상/비대상/확인 필요 수량을 표시하고, 입고 판정·근거와 재고·출고 기록을 ID 기준으로 나란히 표시한다. 변경된 기록만 보기와 20건 단위 페이지 이동을 제공한다. 한쪽에 없는 기록은 0으로 대체하지 않고 기록 없음으로 표시한다. 출고 연결 미확인 수량은 별도로 보존하며 확인 필요 수량과 합산하지 않는다.

데이터 버전이 달라지면 경고와 양쪽 조건·데이터 ID를 표시한다. 같은 기록 ID는 화면의 비교 키일 뿐 동일 실물·거래의 증명이 아니다. 증감은 작업 완료·회수 실적 또는 AI 성능 개선을 의미하지 않는다. 조건 원문 차이 분석이나 기록 간 자동 연결은 수행하지 않는다.

기존 사건별 판정 조회 API를 재사용하고 서버 상태는 변경하지 않는다. 선택 변경 시 이전 결과를 지우며 늦게 도착한 이전 요청 결과를 표시하지 않는다. 판정이 2개 미만이면 안내하고 같은 판정끼리의 실행은 막는다. 두 역할 모두 기존 조회 권한으로 사용할 수 있다.

## 검토 대기함

검토자는 검토 대기함 메뉴 또는 업무 대시보드의 바로가기에서 조건 승인·입고 증거·작업 증빙을 모아 조회한다. 유형과 사건·항목 검색을 제공한다. 조건·증빙 링크는 해당 기록을 강조하고, 입고 증거 링크는 해당 검토 상세를 연다. 경로 쿼리가 달라지면 상세를 다시 로드해 이전 선택이 남지 않게 한다. 직접 `/reviews`에 접근한 실행 담당자에게는 제한 안내를 표시한다. [조회 기준](workspace-api.md)

## CSV 출처 표시

데이터 관리 → 준비 상태 점검의 데이터 출처·원본 추적에서 직접 CSV 등록과 입고 증거 보완 버전을 구분한다. CSV 파일별 메타데이터를 표시하고 보완 버전은 기준 데이터 및 승인 증거 상세로 연결한다. 기존 정보 없는 버전은 기록 없음으로 안내한다.

## 증거 파일 첨부

입고 증거 제안과 작업 증빙 생성 폼에서 선택적으로 PDF/PNG/JPEG를 첨부한다. 파일 선택 오류는 화면에서 표시하고 서버가 다시 검증한다. 등록과 첨부 저장은 하나의 작업이며 승인·반려 후 추가/교체하지 않는다. 상세에서 등록자·크기·해시와 다운로드 버튼을 제공한다. [첨부 API](attachments-api.md)
