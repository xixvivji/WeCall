# 회수 원문 PDF 가져오기·보관·수정 이력

새 사건 등록 → 텍스트 PDF 선택 → 추출 미리보기 → 원문 채우기 → 사람이 확인·수정 → 사건 등록 → AI 조건 추출 탭에서 요청한다. AI 분석·조건 승인은 자동으로 진행하지 않는다.

## 원본과 원문 버전

미리보기 단계는 영구 저장하지 않는다. 브라우저는 선택한 파일을 보관하고, 사건 등록 때 원본을 다시 전송한다. 서버가 다시 검사·추출하고 미리보기의 파일 SHA-256과 비교한 뒤 원본 파일, 서버 추출본, 사람이 확인한 원문 v1을 함께 저장한다. 사용자가 보낸 추출 텍스트를 서버 추출본으로 신뢰하지 않는다. 미리보기 취소·창 닫기는 서버에 보관 파일을 남기지 않는다.

원본은 기존 `WECALL_ATTACHMENT_DIR`(기본 `~/.wecall/attachments`)에 UUID 파일명으로 보관하며 Git에 포함하지 않는다. DB에는 원래 파일명·크기·해시·쪽 수·등록자·시각·검사 결과와 추출본을 기록한다. DB 등록 실패는 파일 저장도 되돌린다. 프로세스 비정상 종료 후 고아 파일 점검 도구는 증빙 파일과 원본 PDF 양쪽 DB 참조를 모두 확인한다. 파일 저장소와 DB를 함께 백업해야 한다.

원문 수정은 새 버전을 추가하고 이전 버전을 유지한다. 수정자·시각·사유를 세션 신원으로 기록하며 요청자가 작성자를 지정하지 못한다. `expectedVersion` 충돌은 409로 거부한다. 종료 사건은 수정할 수 없다. 처음 등록할 때 확인한 원문은 v1이며 서버 추출본과 별도로 보관한다. 이력 도입 전 사건은 기존 원문을 v1로 이전하되 과거 등록자는 추정하지 않고 null로 표시한다. 이전에 미리보기만 사용한 PDF 원본은 복원할 수 없다.

화면에서 PDF 추출본과 선택한 원문 버전을 나란히 비교할 수 있다. 직접 입력 사건도 원문 버전 관리를 지원하지만 보관 PDF는 없다. 이번 범위는 사건 등록 시 PDF 한 개를 보관하며, 기존 사건에 원본을 소급 첨부하거나 교체·삭제하는 기능은 포함하지 않는다.

## API·권한

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| POST | `/api/v1/source-pdf` | multipart `file` → `{text,pages,scanStatus,sha256}` 미리보기 |
| POST | `/api/v1/recalls/from-pdf` | multipart `file` + JSON `metadata: {recall: {title,sourceType,sourceText}, expectedSha256}` → 사건·원본·v1 원문 등록 |
| GET | `/api/v1/recalls/{id}/source?page=0` | 원본 메타데이터·현재 버전·수정 이력(20개 단위) |
| GET | `/api/v1/recalls/{id}/source/revisions/{version}` | 해당 버전 원문·수정자·사유·서버 추출본 |
| POST | `/api/v1/recalls/{id}/source/revisions` | `{expectedVersion,sourceText,note}` → 새 버전 |
| GET | `/api/v1/recalls/{id}/source/documents/{documentId}/download` | 원본 다운로드 |

조회·다운로드는 REVIEWER/OPERATOR, 생성·수정은 REVIEWER 세션과 CSRF 토큰이 필요하다. 다른 사건의 원본 ID로는 다운로드할 수 없다. 다운로드 전 크기·해시와 활성화된 악성 파일 검사를 확인하고 `DOWNLOAD_REQUESTED` 감사 기록을 남긴다. 응답은 attachment·no-store·nosniff로 제공한다. 원문 조회도 no-store다. 단일 회사 MVP의 기존 권한 범위를 사용하며 회사별 다중 테넌트 격리는 별도 범위다.

## AI와 과거 기록

AI 요청은 원문 내용·해시와 함께 `sourceVersion`을 저장한다. 원문 변경 후에도 과거 분석 결과는 유지하지만 해당 결과를 새 조건으로 전환하려 하면 409로 차단한다. 원문을 예전 내용과 동일하게 복원해도 버전이 다르면 차단한다. 진행 중인 분석은 요청 당시 원문으로 완료될 수 있다. 기존에 만들어진 조건·승인·판정은 자동 수정하거나 취소하지 않으므로 담당자가 현재 원문에 맞게 다시 검토해야 한다.

## 제한

- Spring 서버에서 PDFBox로 처리하며 외부 문서 처리 API를 호출하지 않는다.
- 최대 10 MiB, 1~50쪽, 추출 결과 100,000자. 초과는 거부하고 잘라서 반환하지 않는다.
- 암호화·손상 PDF는 거부한다. 텍스트 없는 스캔 PDF는 422와 수동 입력 안내를 반환한다. OCR은 미구현이다.
- 기존 검사 설정을 사용한다. 활성화 시 파싱 전에 검사하며 감염·검사 장애는 차단한다. 기본 비활성은 NOT_SCANNED로 표시한다.
- 동시 추출은 2건이다. PDF 파서의 프로세스 격리나 강제 실행 시간 제한을 제공하지는 않는다.
- 표·다단·부분 스캔 PDF는 누락이나 읽기 순서 변경이 있을 수 있으므로 원본과 대조해야 한다.
- 로컬 AI의 6,000바이트·80줄 한도는 별도 적용된다.

미리보기는 기존 입력을 자동 덮어쓰지 않는다. 적용 전에 교체 확인을 받고, 미리보기를 적용하거나 버리기 전에는 등록을 막는다. 원문·선택한 파일·수정 사유는 이탈 방지 대상이며 새로고침 후 자동 복구하는 기능은 없다.
