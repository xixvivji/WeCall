# 회수 원문 PDF 가져오기

새 사건 등록 → 텍스트 PDF 선택 → 추출 미리보기 → 원문 채우기 → 사람이 확인·수정 → 사건 등록 → AI 조건 추출 탭에서 요청한다. AI 분석·조건 승인까지 자동으로 진행하지 않는다.

`POST /api/v1/source-pdf`는 REVIEWER 세션과 CSRF 토큰이 필요하다. multipart `file` 하나를 받고 `{text,pages,scanStatus}`를 반환한다. 응답은 `Cache-Control: no-store`다. Spring 서버에서 PDFBox로 처리하며 외부 API를 호출하지 않는다.

- 최대 10 MiB, 1~50쪽, 추출 결과 100,000자. 초과는 거부하며 잘라서 반환하지 않는다.
- 암호화·손상 PDF는 거부한다. 텍스트가 없는 스캔 PDF는 422와 수동 입력 안내를 반환한다. OCR은 미구현이다.
- 기존 악성 파일 검사 설정을 사용한다. 검사 활성화 시 PDF 파싱 전에 검사하며, 감염·검사 장애는 진행을 차단한다. 기본 비활성 상태는 NOT_SCANNED로 표시한다.
- 동시 추출은 2건으로 제한한다. 이는 PDF 파서의 프로세스 격리나 강제 실행 시간 제한을 제공하는 것은 아니다.
- PDF를 영구 저장하거나 DB에 추출 이력을 만들지 않는다. 요청 처리 중 메모리/서블릿 임시 업로드 파일은 사용할 수 있다. 최종 사건에는 사용자가 확인한 텍스트만 기존 sourceText로 저장한다. 원본 보관·다운로드·원본과 수정본의 이력 추적은 별도 후속 범위다.
- 표·다단 편집·부분 스캔 PDF는 텍스트 누락이나 순서 변경이 있을 수 있으므로 원본과 대조해야 한다. 텍스트 일부가 있다고 이미지 영역까지 추출한 것으로 간주하지 않는다.
- 기존 로컬 AI 한도 6,000바이트·80줄은 별도로 적용된다. 문서 전체 추출 성공이 AI 분석 가능을 의미하지 않으며 필요한 범위는 사용자가 검토한다.

미리보기는 기존 입력을 자동 덮어쓰지 않는다. 적용 시 기존 텍스트가 있으면 교체 확인을 받고, 미리보기를 적용하거나 버리기 전에는 등록을 막는다. 미리보기와 수정 내용은 기존 이탈 방지 대상이다.

검증: PDFBox로 만든 합성 PDF의 텍스트 추출, 빈 페이지·손상·암호화·쪽 수·파일 크기 거부, 검사 실패 우선 차단, REVIEWER/OPERATOR/CSRF, 파일 영구 저장 없음. 브라우저 계약 검증은 모의 추출 응답으로 기존 입력 보존 및 사람 수정본 저장·AI 탭 이동을 확인한다. 실제 회사 문서는 사용하지 않았다.
