# WeCall B2B 프로젝트 개요

기준일: 2026-09-17 · 구현 기준: develop, Flyway V12. 이 문서는 현재 제품 범위이며 [최초 통합 기획안](product-plan-2026-09-09.md)은 원문으로 보존한다. 향후 기능은 [보완 설계·우선순위](design/product-roadmap.md)에 별도로 표시한다.

## 무엇을 만드는가

**식품 유통사가 회수 통보를 받은 뒤, 자사 상품·재고·출고 기록과 대조해 대상과 확인할 항목을 찾고, 담당자의 대응·증빙·종료 검토를 관리하는 웹 업무 서비스다.**

예를 들어 “제조번호 A01 또는 A02이면서 소비기한이 2026-10-31인 제품”이라는 공문을 받으면, 담당자가 원문과 AI 초안을 확인하고 내부 상품을 연결한다. 승인된 조건을 Java가 기록에 적용해 대상·비대상·확인 필요를 계산한다. 출고 연결 기록이 없는 수량은 AI가 추측하지 않고 확인 필요로 남긴다.

제품의 가치는 근거와 미확인 사항을 한 사건에 모으고, 추가 증거로 결과가 어떻게 바뀌었는지 추적하는 데 있다. 대응 시간 감소·오류 감소·고객 구매 의사는 아직 검증할 가설이다.

## 누구의 어떤 업무를 지원하는가

첫 버전은 국내 포장 가공식품 유통사 **한 기업**을 대상으로 한다. 품질·상품관리 담당자가 회수 통보를 접수하고 검토하며, 물류 등 실행 담당자가 배정된 작업을 처리한다. 부서명은 사용자 가설이며 현재 권한은 두 역할이다.

| 역할 | 현재 지원 업무 |
| --- | --- |
| 검토자 REVIEWER | 데이터·사건 등록, 원문 수정, 조건·상품 연결 검토와 승인, 증거·증빙 검토, 작업 배정, 종료·재개, 계정 관리 |
| 실행 담당자 OPERATOR | 업무 자료 조회, 입고 증거 제안, 본인 배정 작업 실행·증빙 제출 |

두 역할 모두 현재 단일 기업 자료를 조회할 수 있다. 다중 기업 격리나 문서별 비밀등급 권한을 구현한 상태는 아니다.

## 사용 흐름과 실제 입력

1. **데이터 준비:** 상품·입고·재고·출고·출고 연결 CSV 5종을 등록하고 누락·오류를 확인한다.
2. **사건 접수:** 공고 본문을 붙여 넣거나 텍스트 PDF를 가져온다. PDF 추출본을 확인·수정하고 사건을 등록한다.
3. **조건 검토:** 로컬 AI가 제조번호·소비기한 조건 초안을 제시한다. 사람이 조건과 내부 상품 연결을 검토하고 별도로 승인한다. AI를 쓰지 않고 수동 작성할 수도 있다.
4. **영향 확인:** 승인 조건에 따른 재고·출고 결과와 확인 필요 수량을 조회·비교한다.
5. **근거 보완:** 입고 증거를 검토·승인하면 새 데이터·판정 버전을 만들고 이전 결과를 보존한다.
6. **대응·종료:** 담당자 작업, 처리 증빙 검토, 종료 점검·승인·재개를 기록한다. 결과 보고서를 조회·인쇄한다.

웹 서비스라는 것은 사용 화면의 형태다. **웹 공고 URL 자동 수집은 아직 없고, 웹 본문은 복사해 입력한다.** 스캔 PDF·이미지의 문자 인식은 제공하지 않는다. 현재 사용자 방향에 따라 OCR은 필수 MVP에서 보류한다.

## 현재 구현 범위

| 영역 | 구현과 중요한 한계 |
| --- | --- |
| 데이터 | CSV 원자적 검증·등록, 준비 상태, 버전·출처 메타데이터; ERP 자동 연동 없음 |
| 원문 | 텍스트 PDF 미리보기·원본 보관·해시 검증 다운로드, 추출본과 수정본 비교, 버전·수정자·사유; 기존 미보관 원본 복원 불가 |
| AI | 로컬 Qwen3 4B Instruct 조건 추출, 근거·사람 검토 화면, 오류 기록; 상품 자동 연결·OCR·긴 문서 자동 분할 없음 |
| 판정 | 사람 승인 조건, 상품 연결, 대상·비대상·확인 필요, 불변 판정 결과와 비교·CSV 내보내기 |
| 대응 | 담당자·작업·증빙·검토·회차별 이력, 종료·재개; 실제 회수 수량 집계나 외부 시스템 조치 실행 아님 |
| 화면 | 사건·대시보드·내 할 일·검토 대기함·원문 이력·보고서, 입력 이탈 방지·오류 재시도·모바일 대응 |
| 파일·접근 | 로컬 파일 저장, 세션·CSRF·역할 검사, ClamAV 연동 어댑터; 실제 검사 엔진 운용·운영 백업은 별도 |

핵심 업무 흐름은 합성 자료로 검증한 개발 MVP다. 실제 고객의 업무 적합성·운영 준비가 완료됐다는 뜻은 아니다. 최신 기록은 [MVP 요구사항](mvp-requirements.md)과 [원문 이력 검증](validation/source-history-2026-09-17.md)을 따른다.

## 책임과 기술

| 영역 | 선택과 역할 |
| --- | --- |
| 프론트 | Vue 3 · TypeScript · Vite: 사람이 입력·대조·승인하는 업무 화면 |
| 백엔드 | Java 21 · Spring Boot 3.5.16 · Gradle 8.7: 권한·업무 상태·조건 판정·수량 계산·파일 처리 |
| 데이터 | PostgreSQL 17.6 · Flyway · Spring JDBC: 원문·입력·조건·결과·이력의 버전 관리 |
| AI 서빙 | Python 3.12 · FastAPI · uv → Ollama `qwen3:4b-instruct`: 제한된 조건 추출 초안 |
| 파일 | Git 밖의 전용 로컬 디렉터리; 운영 저장소·백업·보존 정책은 미확정 |

문서 추론은 외부 모델 API로 보내지 않는 로컬 구성을 선택했다. 모델·의존성 설치 다운로드와 문서 처리는 구분한다. 이 설정이 OS 방화벽·백업·다른 프로그램까지 통제한다는 뜻은 아니다. [구성도](design/architecture.md) · [AI 데이터 경계](design/ai-data-boundary.md)

## 바꾸지 않을 원칙

- AI는 초안을 만들고 사람이 검토한다. 승인 조건의 판정·수량 계산은 Java와 DB가 담당한다.
- 상품 연결, 대상 판정, 대응 작업 상태는 각각 관리한다.
- 누락·충돌은 확인 필요로 남긴다. 실제 출고 연결이 없는 관계를 만들어내지 않는다.
- PDF 원본·추출본·확인한 원문과 과거 판정은 구분해 보존한다.
- 원문 변경 후 이전 AI 결과의 새 조건 전환은 차단한다. 이미 생성·승인된 조건은 자동 취소되지 않으며 재검토 관리가 다음 보완 과제다.
- 작업 완료 건수를 실제 회수·반품 수량이나 법적 완료로 표시하지 않는다.

## 다음 단계와 제외 범위

우선 기존 흐름의 신뢰성을 높인다. **원문 변경의 영향과 재검토 필요 표시, 분석 실패 원인과 해결 방법, 대표 문서 기반 사용성·정확도 검증**이 우선 제안이다. 이후 작업 기한·우선순위와 상품 후보 비교를 검토한다. 구체적 완료 기준은 [보완 설계](design/product-roadmap.md)에 있다. 이 제안은 기능 구현 완료나 후속 개발 착수를 의미하지 않는다.

OCR·배포는 보류한다. ERP·이메일 자동 연동, 외부 판매중지·고객 자동 발송, 복잡한 세트 제조분 추적, 다중 기업 SaaS, 이미지 이해·RAG는 현재 필수 범위에 추가하지 않는다.

원 기획안의 시장 사례·일정·기능 목표는 기획 자료다. 이번 보완에서 외부 근거를 새로 검증하거나, 원 기획안의 지시를 새 실행 지시로 채택하지 않았다.
